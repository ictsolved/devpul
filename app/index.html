DevPul

A debug bridge between a running Dart or Flutter app and your browser. See HTTP calls, errors, session info and custom events live. No proxy, no certificates, no server.

Pul means bridge in Nepali. Open source, MIT licensed.

Get started

  1. Add the packages

    dependencies:
  devpul: ^0.1.0
  devpul_dio: ^0.1.0      # for Dio
  devpul_flutter: ^0.1.0  # for Flutter error hooks

  2. Hook them up

    void main() {
  DevpulFlutter.install();
  Devpul.session({'name': 'My app', 'version': '1.0.0'});
  dio.interceptors.add(DevpulDioInterceptor());
  runApp(const MyApp());
}

  3. Run and connect

    Run the app in debug mode with flutter run or dart run --enable-vm-service. Paste the VM service URL it prints, for example http://127.0.0.1:41234/AbCdEf12=/, into the bar above.

What you get

  • HTTP table with live pending rows, status and method filters, slow request highlighting and copy as curl.
  • Request and response headers and bodies with JSON highlighting, even for large payloads.
  • Flutter and uncaught errors with stack traces.
  • Custom events from Devpul.emit, tag filters and a plugin API for your own panels.
  • Several apps at once, history kept across page reloads, keyboard navigation.
  • Works with Flutter on Android, iOS, desktop and web, and with plain Dart programs.

Questions

How do I see Flutter network requests in the browser?
Add the devpul and devpul_dio packages, add DevpulDioInterceptor to your Dio instance, run the app in debug mode and paste the VM service URL that flutter run prints into DevPul. Requests, responses and errors appear live.
Does DevPul need a proxy, certificates or a server?
No. The app posts events with dart:developer postEvent. The browser reads them from the Dart Development Service websocket on 127.0.0.1. Nothing leaves your machine.
Does DevPul run in release builds?
No. Release and profile builds have no VM service and DevPul never emits in them.
Why does the browser ask to access apps on this device?
Chrome and Firefox ask before a hosted page may connect to 127.0.0.1. Allow it once for this site. Safari blocks such connections; use npx devpul or the downloaded HTML file instead.
How is DevPul different from the Flutter DevTools network tab?
DevPul works for any HTTP client through adapters, including on Flutter web, shows errors and custom events next to requests, filters by tags and app runs, watches several apps at once and keeps history across reloads.
